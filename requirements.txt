# The pod image sets HF_HUB_ENABLE_HF_TRANSFER=1 unconditionally, and
# huggingface_hub treats that as a hard requirement: with the flag on and this
# package absent, any download RAISES rather than falling back to the ordinary
# transfer. It stayed invisible for a long time because every checkpoint was
# already in HF_HOME, so nothing ever downloaded -- the first cold cache (a new
# volume, a cleared cache, a model id that changes) is when it would have
# surfaced, as a failed warm on a running service.
hf_transfer>=0.1.9

# --- headway fast loop ---
# CSRT lives in opencv-CONTRIB, not plain opencv-python, and the tracking API
# moved namespaces in 5.x — headway/tracker.py probes the known homes but the
# <5 pin is what keeps that probe from becoming a real portability problem.
# headless: no GUI libs on a server, and the full build pulls in GTK/X11.
opencv-contrib-python-headless<5

# --- headway lane geometry (UFLDv2) ---
# The lane model is Ultra-Fast-Lane-Detection-v2 (MIT), culane_res18. Its
# architecture is restated in headway/lanes.py and runs on the torch/torchvision
# already pinned above, so there is no new inference dependency -- ONNX was
# considered and rejected (see that module's docstring). gdown is only for
# fetching the 825 MB checkpoint off Google Drive; see tools/fetch_lane_weights.py.
gdown>=5.0

# --- headway object detection (RF-DETR) ---
# RF-DETR (Roboflow), APACHE-2.0. The licence is the reason for the choice:
# Ultralytics YOLO is AGPL-3.0 and cannot ship in this product.
#
# PINNED TO 1.5.0 AND INSTALLED --no-deps, both deliberately:
#   * rfdetr >= 1.6 requires transformers>=5.1, which would drag this repo off
#     the transformers==4.57.0 that Qwen3-VL and Depth Anything are validated
#     on. 1.5.0 declares transformers<5.0.0,>4.0.0 and is compatible.
#   * its dependency list is a TRAINING stack (albumentations, roboflow,
#     rf100vl, pycocotools...). Installing it normally also pulls supervision,
#     which pulls opencv-python 5.x -- and that shadows the deliberate
#     opencv-contrib-python-headless<5 build, taking CSRT and MOSSE with it.
#     Observed: a plain `pip install rfdetr` silently replaced transformers
#     4.57 with 5.14, huggingface_hub 0.36 with 1.25, and left two cv2 builds
#     installed with the tracking API missing from the one that won.
#
# headway/detect.py imports rfdetr.models.lwdetr beneath a stub package object
# so the training harness never executes; supervision/pycocotools/peft are only
# needed to satisfy import statements along that path.
#
# THESE FOUR ARE DELIBERATELY NOT INSTALLABLE FROM THIS FILE. They used to be
# plain requirement lines, which meant `pip install -r requirements.txt` — step
# 3 of boot.sh — installed them WITH the dependency tree the paragraph above
# says must never be installed, and boot.sh's later --no-deps line then found
# them "already satisfied" and did nothing. That is how this pod ended up with
# roboflow, albumentations and opencv-python 5.0.0.93 sitting on top of the
# pinned opencv-contrib-python-headless build, one resolver away from losing
# CSRT. Commented out, the pin is still the single source of the version and
# only boot.sh §5c can act on it, which is where the --no-deps flag lives:
#
#   pip install --no-deps rfdetr==1.5.0 supervision==0.29.1 pycocotools peft
#
